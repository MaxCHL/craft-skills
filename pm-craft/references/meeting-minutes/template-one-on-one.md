# Template — 1-on-1 與主管會議

關鍵詞觸發：1-on-1、one on one、績效、目標、回饋、career、growth、晉升、薪資

---

## 此類會議的特徵

- 雙人，私密
- 內容可能包含敏感資訊（薪資、個人生涯、團隊衝突）
- 結構鬆散，主題跳躍正常
- Action Items 通常分「員工要做」「主管要做」兩類

---

## 隱私警告

⚠️ 1-on-1 紀錄通常**敏感**。處理時：

1. **不在 Appendix 暴露原始逐字稿**，除非使用者明說
2. **私人生活相關片段** — 標 `[私人]`，主要紀錄保留摘要不保留細節
3. **薪資 / 晉升討論** — 完整保留但提醒使用者「此紀錄含敏感資訊」
4. **預設不存到 `./meeting-notes/`** — 改建議存 `./private/1on1/` 或詢問使用者

開頭主動提示：

> ⚠️ 偵測為 1-on-1 紀錄。建議檔案路徑：`./private/1on1/YYYY-MM-DD-{name}.md`，或指定其他位置。是否續行？

---

## 預設議程結構（無議程時）

1. **狀態同步 (Check-in)** — 最近如何、心情、阻礙
2. **進度回顧** — 上次 action items、本週工作
3. **回饋雙向** — 主管給 / 員工給
4. **生涯 / 目標討論**（若有）
5. **下次預定主題**

---

## 特別關注的擷取欄位

### 1. 員工狀態（員工視角）

```markdown
**員工狀態 (Check-in)**
- 心情 / 工作負荷：忙但可控 [推測]
- 主要關注：A 專案 sprint 進度
- 困擾 / 阻礙：與 X 部門協作不順
```

### 2. 進度與成就

```markdown
**進度回顧**
- ✅ 完成：上週 action A1（自學 React 完成 4/5 章）
- 🚧 進行中：A2（codebase walkthrough）
- ❌ 未完成 / 延遲：A3（延後 1 週，因生病）
```

### 3. 雙向回饋

```markdown
**主管 → 員工 回饋**
- 正向：上週的 X 提案邏輯清晰，受跨部門好評
- 改進：與設計師對齊時可更主動 (具體事件：5/8 那次 PR 來回 3 次)

**員工 → 主管 回饋**
- 希望：跨部門協作可更早 align
- 困擾：站會節奏太緊，無法深入
```

### 4. 生涯 / 目標討論

```markdown
**生涯討論**
- 短期 (3 個月)：完成 React 自學，能獨立 own 一個 feature
- 中期 (1 年)：希望挑戰 leading 一個小團隊
- 長期：未明確 [需確認]
- 主管承諾：Q3 安排 mentoring 機會
```

### 5. Action Items（雙向）

```markdown
**Action Items**

| #  | 行動項目 | Owner | Due | 完成條件 |
|----|---------|-------|-----|----------|
| A1 | 完成 React 自學最後一章 | 員工 | 2026-05-21 | 章節習題完成 |
| A2 | 安排與設計師的對齊機制 | 主管 | 2026-05-18 | weekly sync 排入行事曆 |
| A3 | 整理 Q3 mentoring 候選清單 | 主管 | 2026-05-30 | 3-5 位 senior 候選人 |
```

## 1-on-1 紀錄的特別準則

1. **不過度結構化** — 1-on-1 本來就鬆散，逼太緊反而失真
2. **保留情緒訊號** — 「挫折」「擔心」這類情緒詞要保留，但用觀察句而非評判句
   - ✅「員工提到對跨部門協作有挫折感」
   - ❌「員工情緒不穩」
3. **承諾要明確** — 主管的口頭承諾要轉成 Action Item 並標 Owner=主管
4. **回饋分正負** — 主管給的回饋要分「正向」「改進」兩段，不混
5. **避免推測敏感事** — 「我看他壓力很大」這類觀察不寫入紀錄
6. **下次主題清單** — 1-on-1 是連續對話，下次預定主題比 Open Questions 更實用

---

## 不要做的事

- ❌ 把員工的負面回饋當「不滿員工」呈現
- ❌ 把主管的方向當「決議」（除非真的雙方確認）
- ❌ 在 Appendix 留逐字稿（隱私）
- ❌ 自動分享 / 同步到團隊（這份紀錄通常只給兩位當事人）
