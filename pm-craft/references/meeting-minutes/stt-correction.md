# STT 修正規則與標註慣例

「積極修正並標註」策略：能修就修，但**不確定的一律標 `[推測:X]`**，讓使用者能一眼複核。

---

## 標註系統（三層）

| 標註 | 用途 | 範例 |
|------|------|------|
| `[推測:X]` | STT 同音字 / 名詞修正建議；X 為修正後內容 | 「我們要做這個[推測:方案](原:芳安)」 |
| `[需確認]` | 資訊缺漏（人名、日期、Owner 等） | `Owner: [需確認]` |
| `[unclear]` | 完全無法判讀；保留原文於 Appendix | 「(03:12-03:18) [unclear]」 |

**選擇規則**：
- 修正後語意通順 + 領域詞匹配 → `[推測:X]`
- 完全空缺（無 X 可寫）→ `[需確認]`
- 雜訊 / 講者重疊 / 收音不良 → `[unclear]`

---

## 贅字白名單（直接刪除）

中文口語高頻贅字，從正式記錄中**完全移除**：

```
嗯、欸、啊、喔、呃、呀
那個、這個（當填充詞時，非指示代名詞）
就是、就是說、然後就、所以說
對對對、對啊、是是是
你知道、你懂的、我跟你講
那、那麼、就
基本上、大概、應該、好像（若為冗詞）
```

**例外**：以下情況**保留**：
- 「對」做明確同意 / 反對的回應（「對，我同意」）
- 「應該」「好像」表達不確定（語意關鍵）
- 「就是」用於並列（「A 就是 B」）

## 人名 / 公司名 / 產品名處理

1. **第一次出現** — 若 STT 結果不像常見人名 / 品牌，標 `[推測:王經理]`
2. **後續出現** — 沿用首次推測，**不重複加 `[推測]`**
3. **同段內出現多種拼法** — 統一為最常出現的版本，並在 Appendix 註明「以 X 表示 STT 中的 Y/Z」
4. **完全不知道是誰** — 用角色代稱（「主持人」「工程師 A」）+ `[需確認]`

範例：
```
**[王經理]**:[推測] 我們上次跟 ⟨某客戶⟩ 那邊談的...
(後續) **[王經理]**: 對，我們上次 ⟨某客戶⟩ 提的方案...
```

## 標點重建

STT 通常無標點或亂標。重建準則：

1. **句號** — 完整 SVO 結束、語氣下沉、有明顯停頓
2. **逗號** — 分句、條件子句、並列項目
3. **冒號** — 列舉、引用、解釋
4. **問號** — 「嗎」「呢」「吧」結尾的疑問
5. **括號** — 補充說明（STT 不會給）
6. **長句拆分** — 超過 40 字的長句強制斷句；用句號或分號

**範例**：

❌ 原始 STT：
> 那我們今天主要是討論 Q3 的 roadmap 嗯然後我覺得我們應該先把小兒疫苗 PoC 做完再來看成人版因為成人版的市場其實沒有那麼大而且競品比較多

✅ 修正後：
> 我們今天主要討論 Q3 的 roadmap。我覺得我們應該先把小兒疫苗 PoC 做完，再來看成人版。因為成人版的市場其實沒有那麼大，而且競品比較多。

## 數字 / 日期 / 時間 Normalize

**基準**：以對話的「今日日期」為錨點。

| STT 原文 | Normalize |
|---------|-----------|
| 禮拜四 / 週四 | YYYY-MM-DD (週四) — 推算最近的週四 |
| 下週一 | YYYY-MM-DD (週一) |
| 月底 | 該月最後一個工作日 |
| Q3 | 2026 Q3（除非已明確跨年） |
| 三點半 | 15:30 |
| 早上九點 | 09:00 |
| 一千多萬 | NT$10M+（或保留原文於括號） |
| 兩成 | 20% |
| 一半 | 50% |
| 三分之一 | 33% |

**例外**：使用者習慣表達（如「禮拜四」）若是會議文化的一部分，可在括號內保留原文：「2026-05-15 (週四，原文：禮拜四)」。

## 講者標籤 Normalize

統一格式：`**[姓名 或 角色]**:`

### 規則

1. **第一次出現** — 用最完整的稱呼（「王明德經理」），後續可縮為「王經理」
2. **同一人多個別名** — 統一為主標籤；其他別名在 Appendix 註明
3. **匿名 / 不確定** — 「主持人」「工程師 A」「客戶」+ `[需確認]`
4. **多人同時說話** — 「**[眾人]**:」或拆成多行

### 範例

❌ 原始 STT：
```
王: 我覺得...
allen: 對啊
王經理: 那就這樣決定
A: 好
```

✅ 修正後（假設 Allen 就是王經理）：
```
**[王經理]**: 我覺得...
**[工程師A]** [需確認]: 對啊。
**[王經理]**: 那就這樣決定。
**[工程師A]** [需確認]: 好。
```
（Appendix 註明：王經理 = Allen = 王，STT 中混用）

## 強力潤稿模式（僅在使用者明說時啟用）

預設**不開**。使用者說「強力潤稿」「改成書面語」「美化文字」才啟用：

- 合併重複表達
- 改寫為主動句
- 移除過多修飾詞
- 結構重組為「總分總」

**啟用後仍守底線**：
- 不改變語意
- 不刪除反對意見
- 不省略 `[unclear]`
- 在 Appendix 註明「本份記錄已強力潤稿」

---

## Anti-Patterns

- ❌ STT 不確定時直接寫死，不加 `[推測]`
- ❌ 為了排版整齊把人名「猜」成 CEO（用角色代稱比假名好）
- ❌ 刪掉看不懂的整段（必須標 `[unclear]` 保留）
- ❌ 把「應該」「好像」這類表達不確定的字當贅字刪掉
- ❌ 把反對方的「對」（同意對方論點）解讀成「同意決議」
