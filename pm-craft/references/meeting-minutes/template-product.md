# Template — 產品 / 業務決策會議

關鍵詞觸發：roadmap, OKR, KR, GTM, 競品, pricing, 上線, 業務, 客群, milestone

---

## 此類會議的特徵

- 跨部門（PM、Eng、業務、Marketing）
- 涉及優先級排序、資源分配、市場時機
- 通常有「砍掉某些 feature」「延後某條線」這類取捨
- Decisions 數量多，Action Items 跨部門

---

## 預設議程結構（沒有議程時的推測順序）

1. **回顧** — 上次 action items 完成度、KPI 數字
2. **新資訊 / 變化** — 競品動態、客戶回饋、數據洞察
3. **取捨討論** — 優先級排序、資源分配
4. **下一步** — 確認 Action Items

---

## 特別關注的擷取欄位

除了通用的 Decisions / Action Items，額外抓：

### 1. KPI / 指標數字

凡是會議中提到的數字（轉換率、CAC、MAU、ARR、流量），都記下：

```markdown
**指標快照**（會議當下提及）
- 成人版 CPA：NT$1,500（高於目標 40%）
- 小兒疫苗 LP 轉換率：[需確認]
- Q2 ARR：NT$2.4M
```

### 2. 競品動態

```markdown
**競品近況**
- 競品 Y：已切入小兒疫苗（5/10 上線），訂閱方案 NT$199/月
- 競品 Z：暫無動作 [推測]
```

### 3. 優先級表

若會議排了優先級，用表格呈現：

```markdown
**Q3 優先級**

| 優先級 | 項目 | 預期上線 | Owner |
|--------|------|---------|-------|
| P0 | 小兒疫苗 PoC | 2026-07-31 | 林工程師 |
| P1 | 訂閱付費流程 | 2026-08-15 | 張產品 |
| P2 | 成人版 (暫緩) | TBD | — |
```

### 4. 資源缺口

```markdown
**資源缺口 / 阻礙**
- 工程：缺 1 名 Mobile 開發（已開職缺）
- 法務：醫療廣告 review 需外部顧問
```

## Detailed Notes

### Topic 1: Q2 成人版 PoC 結果回顧

**背景**
Q1 拍板成人版為 PoC 主軸，原預期 6 月 PMF。

**討論要點**
- **[陳業務]**: 6 月 user testing CPA 達 NT$1,500，高於目標 1,000 的 40%
- **[張產品]**: ARPU 推估 800，CAC > LTV，單位經濟模型不成立
- **[王經理]**: 競品 Y 5/10 切入小兒疫苗，市場窗口縮短

**結論**
共識成人版 PoC 失敗，需轉向 → 對應 D1

### Topic 2: 小兒疫苗 PoC vs 成人版改良

**背景**
是否完全放棄成人版？還是並行？

**討論要點**
- **[張產品]** 反對完全放棄成人版：「我擔心小兒市場規模撐不起 ARR 目標」
- **[王經理]** 回應：先 PoC 驗證，3 個月後重審
- **[陳業務]** 補充：客戶端對小兒疫苗任務的興趣明確（5 家潛在簽約）

**結論**
拍板 Q3 全力小兒疫苗 PoC → D1（成人版資源暫緩，非永久放棄）

### Topic 3: 訂閱 vs CPA 商業模式

**背景**
Q1 採 CPA，但 CAC 過高。是否改訂閱？

**討論要點**
- **[張產品]** 提案訂閱 NT$199/月
- **[林工程師]** 提醒：訂閱需建立用戶帳號系統，6 週工程
- **[王經理]** 折衷：3 個月雙模式試行，以數據決定

**結論**
試行訂閱 + CPA 雙模式 → D2

## 此類會議的常見陷阱

1. **「再評估一下」不算決議** — 放 Open Questions
2. **跨部門 Action 一定要拆到個人** — 「業務團隊跟進」不行，要寫「陳業務跟進」
3. **預算 / 數字不確定就標 `[需確認]`** — 不要用大概
4. **競品資訊一定來源化** — 「聽說 Y 上線了」標 `[推測]`，並補一句「待驗證」
